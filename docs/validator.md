## Prompt-validator alignment procedure

Before changing any prompt, writer, or validator: identify the exact runtime/version; read the prompt, implementation, tests, fixtures, and persisted contract together; list accepted and rejected boundary cases; search for related validators; run provider-free tests; inspect the exact failed rows/cases; and document false-positive/false-negative trade-offs. Do not weaken a validator to make a canary pass. A production promotion requires separate authorization and a live verification plan.

Any validator, test location, or rule not listed as confirmed above is unverified.
